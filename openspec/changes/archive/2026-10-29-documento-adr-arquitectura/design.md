# Design

## Context

The project does not have a `docs/architecture/` folder nor a `docs/architecture/adr.md` file. Architecture decisions (patterns, layers, technologies, databases, APIs, authentication, deployment) are scattered across code, configuration, comments, and existing documentation (see `openspec/standards/architecture.md` and the specs of `solution-structure`, `api-layer`, `persistence-layer`, etc.). The motivation and scope of the change are in `proposal.md - Why` and `proposal.md - What Changes`; this design focuses on the "how".

Per the OpenSpec/SDD documentation standard in `openspec-documentation-language.md`, all documents generated by OpenSpec related to SDD must be written in English. Therefore, the ADR document (`docs/architecture/adr.md`) must be written in English.

## Goals / Non-Goals

**Goals:**
- Create `docs/architecture/adr.md` following the classic ADR format: number, title, status (proposed/accepted/obsolete), context, decision, consequences, and alternatives considered
- Gather architecture decisions already implemented in the project into a decisions index with complete ADR blocks
- If no previously documented decisions are found, leave `adr.md` as an empty template that explicitly states no decisions are registered yet, with an example of how to register a new decision
- Write the ADR document in English (per `openspec-documentation-language.md`)

**Non-Goals:**
- Do not modify production code, APIs, dependencies, or systems of the project
- Do not create or modify capability specifications (`skip_specs: true` in `.openspec.yaml`)
- Do not generate individual ADR files per decision (the user requested a single document `adr.md`)

## Decisions

| Decision | Rationale | Alternatives considered |
|----------|-----------|-------------------------|
| Location: `docs/architecture/adr.md` | Meets the user's requirement to place it in `docs/architecture` with name `adr.md` | `docs/adr.md` (rejected: does not follow the requested folder); `docs/architecture/decisions.md` (rejected: different name than requested) |
| Single combined document | The user requested "for now only this single document (adr.md)" | Several files `adr-001.md`, `adr-002.md`... (rejected: does not meet the single-file requirement) |
| Classic ADR format per decision | Number, title, status, context, decision, consequences, alternatives | Free format (rejected: does not provide traceability or standard structure) |
| Statuses: proposed / accepted / obsolete | Matches the statuses requested by the user | Add "rejected" (rejected: not requested) |
| Empty template if no decisions | Avoids asserting unverified decisions; gives a clear starting point | Leave the file blank without instructions (rejected: less useful for the maintainer) |
| ADR written in English | Complies with the OpenSpec/SDD documentation standard in `openspec-documentation-language.md` | Spanish (rejected: does not comply with the English standard) |

## Risks / Trade-offs

- [The decisions index may be incomplete if not all implemented decisions are discovered] → Mitigation: clearly mark found decisions and leave sections open for future additions
- [A single combined file may grow large over time] → Mitigation: document in the file when to consider splitting into individual ADRs

## Migration Plan

Not applicable: it is a documentation-only change, with no deployment or rollback over production code.

## Open Questions

None. All design decisions are resolved by the user's scope (single file `docs/architecture/adr.md`, classic ADR format, English language, no behavior changes).
